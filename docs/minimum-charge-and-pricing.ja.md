# AI API の最低チャージと料金を確認する方法

AI API の費用は「1M token あたりの表示単価」だけでは比較できません。**最低チャージ額、入金時のクレジット換算、入出力とキャッシュの課金、未使用残高、検証日**を同じ表にそろえると、実際に支払う総額を判断しやすくなります。

> **主な操作**：候補ごとに「最低入金額、入金後クレジット、換算率、対象モデルの入力・出力・キャッシュ単価、状態ページ、最終確認日」を1枚の比較表へ記録してください。

接続先の例は [`nuoapi.net`](https://nuoapi.net) です。モデル ID、グループ、倍率、可用性は変わるため、現在値は[モデル広場](https://nuoapi.net/model-plaza)と管理画面で確認してください。表示価格が同じでも、最低入金額やクレジットの有効期限が違えば初期費用は変わります。

入力・出力・キャッシュと最低入金をまとめて試算する場合は、[1M Token あたりの実費計算機](cost-per-1m-tokens.ja.md)を使います。

## 1. 最初に分ける三つの価格

| 価格 | 意味 | 確認する場所 |
|---|---|---|
| 公式 API 価格 | モデル提供元が公表する入力・出力・キャッシュ等の基準 | 提供元の料金ページ |
| ゲートウェイ表示価格 | グループ倍率や販売価格を反映した表示 | モデル広場と管理画面 |
| 実効支払価格 | 最低入金額、クレジット換算、期限、手数料を含む実際の負担 | 入金画面、請求書、利用履歴 |

「安い」と判断する前に、三つが同じ単位か確認します。`$ / 1M tokens`、`元 / 1M tokens`、社内クレジット、回数券、月額プランをそのまま並べると比較を誤ります。

## 2. 最低チャージ額の計算

最初の支払額は、モデル単価より最低入金額で決まることがあります。

```text
初回支払額 = 最低チャージ額
受取クレジット = 最低チャージ額 * クレジット付与率
実効クレジット単価 = 初回支払額 / 受取クレジット
```

例えば 100 の支払いで 100 クレジットなら換算率は 1.0、100 の支払いで 80 クレジットなら実効単価は 1.25 です。ボーナスや期間限定クレジットは、有効期限と利用可能なグループを確認してください。

未使用残高がある状態で次の最低入金額へ到達する必要があるなら、その拘束額も比較表に入れます。残高が返金可能か、アカウント間で移せるか、期限後に失効するかは、表示価格とは別の条件です。

## 3. 1 リクエストの料金

基本式は次のとおりです。

```text
リクエスト料金 =
  入力 token / 1,000,000 * 入力単価
  + 出力 token / 1,000,000 * 出力単価
  + キャッシュ書込量 * 書込単価
  + キャッシュ読取量 * 読取単価
  + 画像・音声・検索・ツール等の追加料金
```

入力欄が空に見えても、ゲートウェイが system prompt や安全指示を追加している場合があります。請求明細の入力 token と、アプリケーション側で数えた token が一致しないときは、固定プレフィックス、リトライ、会話履歴、ツール結果のどれが増えたかを分けて確認します。

キャッシュは「安くなる機能」と一律に扱わず、書込みと読取りを別々に記録します。キャッシュ読取りにも料金が付く場合があるため、単価表の小さい注記まで確認してください。

## 4. 比較表の作り方

最低限、次の列を用意します。

| 項目 | 記録例 | 判定 |
|---|---|---|
| モデル ID | 管理画面の文字列を完全一致で転記 | preview や日付接尾辞を落とさない |
| 入力単価 | 通貨、単位、税の扱いを含める | `$ / 1M tokens` 等へ統一 |
| 出力単価 | 入力と別に記録 | 出力の方が高い場合を反映 |
| キャッシュ | 書込み・読取り・保存期間 | 無料と決めつけない |
| 最低入金額 | 初回と継続時を分ける | 残高との差を確認 |
| クレジット換算 | 支払額と付与額 | 実効単価を計算 |
| 状態ページ | URL と確認日時 | 稼働保証とはみなさない |
| SLA | 文書の有無と測定条件 | 状態ページだけで代用しない |
| 最終確認日 | ISO 8601 の日付 | 古い表を現在価格として使わない |

同じモデル名でもグループや契約で倍率が変わる場合、公開表の価格と自分の管理画面の価格を分けます。**公開価格は自分の実効価格ではない**ため、見積では両方を残します。

## 5. 月額コストの見積

代表的な一か月を次の式で試算します。

```text
月額変動費 =
  Σ(入力 token * 入力単価)
  + Σ(出力 token * 出力単価)
  + Σ(キャッシュ書込・読取料金)
  + 追加機能料金

月額総額 = 月額変動費 + 固定費 + 最低入金による未使用拘束額
```

平均だけでなく、短い質問、長い文脈、画像、ツール呼び出し、失敗リトライを別々に試算します。過去の利用ログがあるなら、月間 token 数だけでなく、リクエスト数、最大入力長、出力比率、キャッシュ命中率も使います。

料金ページの更新日が古い、または通貨換算日が明記されていない場合は、その不確実性も表に残します。推測した数字を確定値として扱いません。

## 6. SLA と状態ページの読み方

状態ページは障害やメンテナンスの履歴を示しますが、それ自体は返金条件や可用性保証ではありません。SLA を確認するときは、測定対象、集計期間、除外条件、申請期限、補償額、地域・モデル別の適用範囲を読みます。

接続先が複数ある場合は、どのモデルがどの国・地域で処理されるか、障害時に別モデルや別リージョンへ切り替わるかを確認します。切り替えでモデル ID が変わると、可用性が保たれても応答品質や料金条件が変わる可能性があります。

モデルの同一性を確認する方法は[モデル検証の方法論](MODEL_VERIFICATION_METHODS.md)にまとめています。最初は課金なしの自己テストを行い、結果を **一致 / 不一致 / 証拠不足** の三状態で記録してください。

## 7. 公開前チェック

1. 価格の通貨、税、請求単位、更新日を記録した。
2. 最低入金額と実効クレジット単価を計算した。
3. 入力、出力、キャッシュ、追加機能を分けた。
4. 公開価格と自分の管理画面の価格を分けた。
5. 状態ページと SLA 文書を別の証拠として保存した。
6. 次回確認日を決め、古い価格表を現行値として再利用しない。

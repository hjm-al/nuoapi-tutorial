## 1. 请求格式

接口地址：

```text
POST https://nuoapi.net/v1/images/generations
Authorization: Bearer YOUR_NUOAPI_API_KEY
Content-Type: application/json
```

最小请求：

```json
{
  "model": "MODEL_NAME_FROM_MODEL_PLAZA",
  "prompt": "一只白猫，干净背景，写实风格，无文字无水印",
  "n": 1,
  "size": "1024x1024",
  "quality": "medium",
  "output_format": "png"
}
```

模型名应从当前 Key 能看到的模型列表或模型广场复制。列表出现不等于当前分组、上游账号池和权限一定可调用。

## 2. PowerShell 调用

把 Key 只放在当前 PowerShell 会话中：

```powershell
$env:NUOAPI_KEY = "YOUR_NUOAPI_API_KEY"
$headers = @{
  Authorization = "Bearer $env:NUOAPI_KEY"
  "Content-Type" = "application/json"
}

Invoke-RestMethod `
  -Uri "https://nuoapi.net/v1/images/generations" `
  -Method Post `
  -Headers $headers `
  -Body (Get-Content .\body.json -Raw) `
  -TimeoutSec 360
```

请求可能持续几十秒到几分钟。完成后删除会话变量：

```powershell
Remove-Item Env:NUOAPI_KEY -ErrorAction SilentlyContinue
```

也可以把上面的请求体保存为 `body.json` 后自己写一段本地保存脚本（仓库未附带该脚本）。不要把真实 Key 写入教程、图片元数据、截图或 Git。

## 3. 返回图片的两种形态

客户端必须同时处理 Base64 和 URL：

```js
const item = body.data?.[0];
const base64 = item?.b64_json ?? item?.b64 ?? item?.image?.b64_json;
const url = item?.url ?? item?.image_url ?? item?.image?.url;
```

- 有 `b64_json` 或 `b64`：去掉可能存在的 `data:image/...;base64,` 前缀后解码保存。
- 有 `url` 或 `image_url`：再发起下载请求保存图片。
- 保存后读取文件实际宽高和格式；请求的 `size` 不能替代交付检查。
- URL 可能指向第三方托管位置，不要上传证件、密钥、内部截图等敏感素材。

### 编辑与多张生成的边界

- 同步图像编辑曾以 `POST /v1/images/edits` 的 JSON 请求形状成功返回图片；这只证明提示词驱动的编辑请求可用，不等于验证了 mask、像素级局部锁定或 multipart 上传。
- **这个入口不是 OpenAI 官方那种 `multipart/form-data`，而是 JSON**：源图放在 `images[]` 数组里，字段名为 `image_url`。跨实现时这一点最容易踩空——按官方文档拼 multipart 会失败。
- `images[].image_url` 必须是服务端能访问的 URL。**本地文件路径不能直接填**；若要传本地图，得先转成 data URL（`data:image/png;base64,...`）内联进去——这条已观察可用，但会显著抬高请求体体积，单张 3 MB 的 PNG 编码后约 4 MB。
- 编辑只验证了提示词驱动这一层。`mask`、多区域坐标、像素级局部锁定均未验证；需要严格局部重绘时先做小额测试，并逐区域比对其他位置有没有被改动。
- 本地批量比较脚本是“每个模型单独发一条 `n=1` 请求”。同模型重复采样也应按每次独立请求计数；图像接口一次 `n>1` 返回多张的能力未充分验证。
- 每次调用可能计费。批量前应先限定模型、请求数量、参数、输出路径和预算，并获得明确授权；不要让失败自动触发未限定重试。
- 想系统性地改提示词、而不是碰运气，见[《图像生成质量复盘方法》](图像质量复盘方法-2026-10-18.md)。

## 5. 选型建议的边界

- 通用成图：先看 `gpt-image-2.5`。
- 明亮节庆宣传：比较 `gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst`。
- 大尺寸纹理观察：尝试 `grok-imagine-image` 或 `grok-imagine-image-quality`，并使用被授权调用 Grok 的 Key。
- `gpt-image-2` 的实际宽高必须在每次保存后读取，不能只相信请求参数。
- 返回格式和图片尺寸可能随模型、参数或测试窗口变化；按文件头/解码结果记录格式，不能只看扩展名。
- 每个模型本轮只生成 1 张，结论属于单次采样观察，不是固定排行榜。正式选型应固定提示词和参数，再做多次采样和人工评分。

# 模型真伪与防掺水：中转站换模型怎么判断

判断 AI 中转站是否换模型、检查模型真伪，先用固定四步跑一遍：**① 锁定同一协议入口并保存原始响应；② 检查字段族、ID 形状与计费单位；③ 在同样本量下比较输出分布；④ 用长上下文或附件暗号验证标称能力。** 这套“AI 中转站 防掺水”流程不靠追问模型身份；结论只写 **匹配 / 不匹配 / 证据不足**，证据不足时继续取样，不能猜成通过。

跨国选型或采购时，建议按 **真实成本 → 模型一致性 → 数据边界 → 稳定性** 四层核对：先从[最低充值、额度换算与公开价差](minimum-charge-and-pricing.ja.md)和[每百万 Token 总成本](cost-per-1m-tokens.md)确认实际支出（另提供 [English](cost-per-1m-tokens.en.md) / [日本語](cost-per-1m-tokens.ja.md) / [Español](cost-per-1m-tokens.es.md) / [繁體中文](cost-per-1m-tokens.zh-Hant.md)），再用本页区分模型身份，随后按[企业网关检查表](llm-gateway-checklist.en.md)核对驻留、审计、BYOK 与故障转移，最后把状态页、错误码和复查窗口作为稳定性证据。顺序反过来很容易把“便宜且能连通”误写成“可靠且未换模型”。

> **主操作**：先运行 `python examples/model_verify.py --selftest`，在零请求、零计费的前提下核对探针与统计口径，再决定是否采集真实证据。

> 本文回答一个问题：**怎样用可辩护的证据判断一个 API 端点返回的是不是它声称的那个模型？**
> 配套可跑脚本：[`../examples/model_verify.py`](../examples/model_verify.py)（默认 DRY RUN，不产生任何计费请求）。探针入口见[防掺水检测专题页](../topics/anti-dilution.md)。
>
> 下文的样例端点以[模型广场](https://nuoapi.net/model-plaza)为夹具，方法本身不依赖任何特定网关；换一家只需替换地址与模型名。

## 一、先讲结论

判断模型真伪的主流做法**不是问模型"你是谁"**，而是看它无法伪装的残留痕迹，再用统计方法比对分布。

按判别力从高到低分四类：

| 档 | 信号类别 | 需不需要模型"配合" | 能支撑什么结论 |
|---|---|---|---|
| **A** | 协议与字段残留 | 不需要 | 强：能指出"响应结构更像另一家上游" |
| **B** | 输出分布 / 分词行为指纹 | 不需要 | 强：能给出"两批回答统计上不等价" |
| **C** | 能力埋针（长上下文、附件真读、工具链） | 不需要 | 中强：能证明"某项承诺的能力没有兑现" |
| **D** | 模型自述、合规话术、首字延迟 | 需要 / 受链路支配 | **弱：只能当参考，不能当判定** |

**只有 A/B/C 可以写进"不匹配"的结论；D 类一律不得作为判定依据。**

## 二、A 档：协议与字段残留（成本≈0，优先做）

网关在多家上游之间转换协议时，字段名和 ID 形状很难全部伪造干净。值得断言的点：

- **响应 `id` 前缀**：OpenAI 系通常是 `chatcmpl-`，Anthropic 系是 `msg_`，其它形状说明中间还有一层自研网关；
- **`usage` 的字段命名**：`prompt_tokens/completion_tokens` 与 `input_tokens/output_tokens` 分属不同协议族，混用即暴露转换痕迹；
- **上游计费单位透传**：出现非本站体系的计价字段（例如以 tick 为单位的成本字段），基本可断定上游是商业订阅侧接口；
- **缓存字段语义**：`cached_tokens` / `cache_read_input_tokens` 的增长是否与请求内容规模成比例。**注意：账单核对必须把缓存读取项算进去**，否则会把最贵的一段看成免费；
- **`stop_reason` 枚举取值**：各家枚举词表不同，出现第三方枚举值即为转换层痕迹；
- **响应骨架字段**：标称 OpenAI 协议就该有 `choices`，标称 Anthropic 就该有 `content` + `stop_reason`，标称 Gemini 就该有 `candidates`。缺顶层字段说明这个路径根本没按所声称的协议回源；
- **响应头**：`X-Request-Id` 的格式是否在同一链路里被**重复追加**（UUID 与裸 32 位十六进制混用说明经过多跳）、网关自答与真正上游回源在缓存头上是否可区分。**取证注意**：多数 HTTP 客户端把响应头转成字典时只会留下同名头的第一个值，必须用 `get_all()` 之类的接口取全量，否则多跳痕迹会被静默吞掉。

**取证纪律**：字段比对必须**同一路径、同一协议入口、同一 UA** 做对照。换入口往往只是换个字段名，不代表换了模型——把入口差异误读成"模型被换"是最常见的假阳性。同理，**"声称的协议族"必须与实际请求的路径绑定**：拿 `--claims anthropic` 却去打 `/v1/chat/completions`，再用 Anthropic 的字段表去核对，得到的"不匹配"是自造的假案。

## 三、B 档：输出分布指纹（成本几分到一毛）

原理：即使 temperature 固定，不同底座在"只输出一个词/一个数"这类窄约束题上的答案分布不同（随机数偏好、颜色与月份选择、缩写展开习惯）。

做法：

1. 用 30–40 道单字/单数探针（`model_verify.py` 用 37 道，含 6 道中文题），`max_tokens=2`；
2. **按选项基数把探针分成两类，统计量不能混用**：
   - **闭集题**（硬币、猜拳、星期、月份、1–10 的数字等，选项 ≤ 12）：比对**整份分布**，用 Jensen-Shannon 散度；
   - **开放题**（"说一种动物/宝石/树"，词表近乎无限）：只能比对**集中度**（众数占比）。开放题的 n 次答案天然互不相同，逐符号比分布会把随机性读成调包；
3. **样本量下限**：闭集题每题 n≥8、开放题 n≥5 才允许下结论，否则一律记"证据不足"；
4. **不拍阈值**：对每道探针做置换检验（打乱新旧标签重算统计量，得经验 p 值），再对全部被检探针做 Holm–Bonferroni 校正。注意分辨率约束——m 道探针在 α=0.05 下要求 p < α/m，置换次数必须 > m/α（37 道即需 ≥741 次，脚本默认 2000），否则连"真换货"也只能记证据不足，此时脚本会显式降级而**不会**谎报"与基线一致"；
5. **效应量门槛**：p 显著但散度 < 0.15（或众数占比差 < 0.30）不足以指控调包，只记"证据不足"；
6. **单道不定罪**：至少 2 道探针同时显著且过效应下限，总评才允许"不匹配"；
7. 与被测端点自身的历史基线比（抓漂移），或与官方端点同时段比（抓调包）。**基线必须同入口、同模型、同协议族**，脚本把 `_meta`（端点/模型/协议族/reps/时间）写进基线文件，不同源时直接降级为证据不足。

为什么这么麻烦——本仓库的实测回归：拿**同一个模型**自己采两份 profile 互比，旧的"n=5 + JS>0.35 + 任一道不合格就定罪"口径会在 37 道探针中误判 **21–30 道**"不匹配"；改为分层统计量 + 置换检验 + Holm + ≥2 道门槛后，同分布自比误报 **0 道**，而把输出替换成"每次都回同一个词"的冻住底座仍能一次性定罪 24 道。**旧口径的"不匹配"结论没有对外举证价值。**

适用边界：B 档的合法结论是**"在 n 次重复与 α 水平下不能认为等价"**，而不是"证明是某模型"。分词器差异会直接影响可辨识度；温度、量化、系统提示词前缀都会移动分布。

## 四、C 档：能力埋针

> 自动化范围：本仓库 `model_verify.py --tier C` 目前只实现下列第一项（长上下文针探）；其余三项为手工方法，按本节描述自行设计载荷，并用 `evidence_capture.py` 留证。

不问模型身份，只验证**它是否真具备标称能力**：

- **长上下文针探**：在第 N 千 token 处埋一个随机暗号，只问暗号；同时核对 `usage` 是否真的按该长度计费；
- **附件真读**：把暗号写进 PDF / 图片再上传，看回答里是否出现暗号——**状态码 200 不代表附件被读到**，部分网关会静默丢弃附件块；
- **工具链与结构输出**：`tools` 触发、`response_format` 约束、联网检索是否真返回结果块（检索结果为空数组而模型照常作答，等同于能力未兑现）；
- **条件触发复查**：公开审计中观察到"前若干次请求完全正常、之后才开始动手脚"的投递方式，因此**接入时测一次不算数**，需要不定时抽样复查。

唯一答案的谜题（数数、脑筋急转弯、看图说话）不能单独当降智证据。小模型也会做对其中一部分，做对说明不了「就是那个旗舰」，做错也可能只是题面歧义。C 档要埋的是调用方自己才知道的暗号，不是公开题库。

## 五、D 档：为什么"问模型"不能当证据

1. **自述可被网关改写**。已实测确认：网关会注入长度不等的系统前缀（不同分组从约 11 token 到 4,000+ token 不等），前缀里写什么身份，模型就答什么身份。
2. **关键词命中不是判据**。回答里出现某厂商名称，可能只是模型在正常解释生态；反过来，被替换的底座也可以被提示闭嘴。
3. **合规话术不是国界指纹**。被二次包装的模型同样会拒答，海外模型也可能正面回答同一个问题。
4. **首字延迟受链路支配**。账号池状态、缓存命中、CDN 与并发都会改变 TTFT，用它判"物理上一定在国内"会因一次线路抖动而误判。
5. **问「你是哪一天发布的」证明不了身份**。模型先训练、后发布，训练语料里通常没有它自己的发布日。真模型答不出，不能当成冒牌；答得出，也可能来自系统提示或当次联网。这类问答仍是 D 类。

正确用法：D 类结果**照实记录，标为"低判别力/参考信息"**，不参与结论。评分放在本地脚本里，不把标准答案写进发给模型的提示词，也不让模型给自己打分。

## 六、成本量级参考

| 方案 | 计费请求数 | 量级 |
|---|---|---|
| A 档纯字段取证 | 复用 1 条已有响应即可 | ≈ 0 |
| B 档 37 探针 × n=8（脚本默认） | 296 次 × 1~2 token | 约 $0.02–0.10 |
| C 档长上下文埋针（128k） | 1–3 次 | 数毛到数美元，**取决于倍率与分组** |
| 基准题回归（小样本） | 数十次 | 视题量 |

`model_verify.py` 在真正发请求前会打印**预计请求条数与预估 token**，未加 `--run` 一律不发；`--selftest` 分支完全离线，零请求零计费。

## 七、结论写法（三态制）

每条信号只允许三种结论，并附判别力标签：

- **匹配**：与所声称模型/上游的已知特征一致（说明：一致不等于证明为真）；
- **不匹配**：出现互斥特征（例如协议字段族与声称的上游不符，或 ≥2 道分布探针同时过显著性与效应量门槛），**必须有 A/B/C 档信号支撑**；
- **证据不足**：只有 D 档信号；样本量/重复次数不达标；统计分辨率（置换次数）不足以在多重比较下达到所需 p 值；只有单道探针显著。

禁止的写法：把"没有出现某厂商关键词"写成"通过"，把"响应很快"写成"不是海外模型"，把单一信号写成"100% 掺水"。

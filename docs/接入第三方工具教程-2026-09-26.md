# 接入第三方工具教程

> 本文是独立开发者维护的技术配置说明，与 OpenAI、Anthropic、Google、xAI、DeepSeek、MiniMax 或其他模型厂商不存在官方关联、投资、赞助或合作关系。文中商标和产品名称仅用于协议兼容性说明。\
> 本仓库不提供、不代售任何 API 服务或充值通道。使用第三方服务前，请自行核对服务条款、隐私政策、价格和可用性。

本文以 NuoAPI 这类第三方 AI 网关为例，说明如何把兼容的客户端、命令行工具、IDE 插件或本地 Agent 接入 API。不同工具的菜单名称和配置字段可能随版本变化，最终以目标工具当前文档和账户控制台显示为准。

## 1. 先认清四种协议面孔

客户端设置里名字五花八门，但按**报文协议**归纳只有四种：**Chat Completions、Responses、Messages、Gemini 原生**（Generative Language API）。前两种最早由 OpenAI 提出、第三种由 Anthropic 提出、第四种由 Google 提出，但如今它们都是公开的兼容形态——xAI（Grok）、DeepSeek、MiniMax 等厂商的官方接口也只是复用其中某一种，并**没有各自的私有协议**。所以选型只看客户端"说哪种协议"，不要按厂商名对号入座，也不要把同一种兼容形态按厂商重复计数。

| 协议面孔                 | 实际请求路径（NuoAPI 入口）                                             | 客户端 Base URL 填什么                                                                      | 谁在用                                                                   |
| -------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Chat Completions** | `POST https://nuoapi.net/v1/chat/completions`                 | `https://nuoapi.net/v1`                                                               | 绝大多数标称 `OpenAI Compatible` 的桌面端、IDE 插件（Cline/Roo/Continue）、Aider；xAI（Grok）、DeepSeek、MiniMax 等的官方接口也是这一形态 |
| **Responses**        | `POST https://nuoapi.net/v1/responses`                        | `https://nuoapi.net/v1`                                                               | Codex CLI / Codex 桌面端、明确写 `responses` / `wire_api = "responses"` 的新工具 |
| **Messages**         | `POST https://nuoapi.net/v1/messages`                         | `https://nuoapi.net`（**根地址，不加 /v1**）                                                  | Claude Code、Claude Desktop 第三方推理（Cowork）                              |
| **Gemini 原生**        | `POST https://nuoapi.net/v1beta/models/{模型名}:generateContent` | 原生 REST 填 `https://nuoapi.net/v1beta`；Gemini **CLI 例外**，环境变量填根地址 `https://nuoapi.net` | Gemini CLI、直接调 `generateContent` 的脚本                                  |

> Base URL 与完整请求地址不是一回事：Base URL 是"前缀"，客户端会自己在后面拼 `/chat/completions`、`/responses`、`/v1beta/models/...` 等路径。只有工具字段明确要求"完整 endpoint / 完整 URL"时才填整条路径。上表的入口规则与仓库 README 的"域名和 Base URL 路由图"一致（取证窗口 2026-09-21）；模型名、分组和协议始终以模型广场当前显示为准。

### 1.1 Chat Completions 与 Responses：同一 Base URL 下的两条路径

两者是**同一 Base URL 下的两条路径、两套报文结构**，不要看到名字相近就以为随便选：

- **Chat Completions**（`/v1/chat/completions`）：最通用、生态最广的经典对话接口。看到 `OpenAI Compatible`、`API Base`、`base_url` 字样的工具，九成走它。
- **Responses**（`/v1/responses`）：OpenAI 新一代接口，Codex CLI/桌面端默认走它。配置文件里通常写作 `wire_api = "responses"`（选另一个时常见值为 `chat` / `chat_completions`，以工具文档为准）。
- 选错的典型表现：路径 404、报文字段不认识的 400，或连上了但流式行为异常。Codex 还需要关闭 WebSocket（`supports_websockets = false`），否则会一直 `Reconnecting`。

### 1.2 Messages：Base URL 填根地址

Messages 协议只有一张面孔，但 Base URL 规则与前两个协议相反——**客户端里填根地址** **`https://nuoapi.net`，客户端自己拼** **`/v1/messages`**。把 Chat Completions 习惯的 `/v1` 带上反而 404。环境变量通常是 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`。

### 1.3 其他厂商（xAI Grok、DeepSeek、MiniMax 等）：没有第五种协议

这些厂商的官方接口（如 xAI 的 `api.x.ai`）本身就采用 Chat Completions 兼容形态，没有独立的报文协议。经中转站使用它们的模型时，统一按 1.1 的 Chat Completions 接：`https://nuoapi.net/v1` + Key + 模型广场里的对应模型名。能否调到某个模型取决于当前 Key 分组，判定只看调用记录与返回，不凭客户端列表里有没有出现厂商名字。

### 1.4 Gemini 原生：REST 与 CLI 两种填法

- **原生 REST / 脚本直调**：Base URL 用 `https://nuoapi.net/v1beta`，路径形如 `/v1beta/models/{模型名}:generateContent`。
- **Gemini CLI**：环境变量 `GOOGLE_GEMINI_BASE_URL=https://nuoapi.net`（根地址），配 `GEMINI_API_KEY` 和 `GEMINI_MODEL`，不要手加 `/v1beta`。
- 报 `400 platform is not gemini` 一类错误，优先怀疑入口/协议平台不匹配，而不是 Key 问题。

### 1.5 MCP 不是模型协议

MCP（Model Context Protocol）是本地工具扩展协议（文件系统、浏览器、数据库等），和上表四种模型 API 协议是两件事，配置位置互相独立。详见第 8 节。

## 2. 准备三个值

接入前准备：

1. API Key：从服务控制台创建，使用专门的测试 Key。
2. 模型名：从当前账户可见的模型列表或模型广场复制，不要凭印象填写。
3. 协议地址：按第 1 节选对 Base URL，不要把不同协议的地址混用。

API Key 只放在本机环境变量或工具的凭据存储中。不要提交到 Git、截图、公开 Issue、前端 JavaScript 或 CI 日志。示例文件只使用：

```text
YOUR_NUOAPI_API_KEY
```

## 2.5 先安装命令行客户端（Node.js 与 CLI）

图形界面客户端（Cherry Studio、ChatBox、LobeChat 等）无需本节，直接跳到第 3 节。要使用 Claude Code、Codex CLI、Gemini CLI 这类命令行工具，先装 Node.js，再用 npm 装对应 CLI。

### 2.5.1 安装 Node.js

要求 Node.js 18 以上（建议 20 LTS 或更新），npm 随 Node.js 一起安装，无需单独装。

- **Windows**：推荐用 winget 一键安装：`winget install OpenJS.NodeJS.LTS`；也可到 <https://nodejs.org> 下载 LTS 安装包，双击按提示安装。
- **macOS**：`brew install node`（Homebrew），或到 nodejs.org 下载安装包。
- **Linux**：用发行版包管理器，或用 nvm 安装（便于切换版本）。

安装后**新开一个终端**验证（安装前已经打开的终端读不到新 PATH）：

```bash
node -v
npm -v
```

两行都出现版本号即可，例如 `v20.11.1` 和 `10.2.4`。只出版本号、不报错，再继续下一步。

Windows 上两个常见拦路虎（本机实测）：

- **PowerShell 执行策略拦截**：运行 npm 或全局命令时报"无法加载文件……因为在此系统上禁止运行脚本"，是 npm 生成的 `.ps1` shim 被拦。改用 `.cmd` 入口（如 `npm.cmd install ...`、`codex.cmd --version`），或执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` 放开当前用户的脚本权限。
- **装完仍提示命令不存在**：确认 Node.js 没装在临时目录；npm 全局 bin 目录（`npm config get prefix` 显示的路径）要在 PATH 内。安装后必须新开终端。

### 2.5.2 安装 CLI（按需安装，不必三个都装）

```bash
npm install -g @anthropic-ai/claude-code   # Claude Code
npm install -g @openai/codex@latest        # Codex CLI
npm install -g @google/gemini-cli          # Gemini CLI
```

分别用 `claude --version`、`codex --version`、`gemini --version` 验证，出现版本号即安装成功。提示 `command not found` 时，先按 2.5.1 末尾两条排查（PATH 与执行策略），不要反复重装。

装好 CLI 之后，再回到第 3 节判断你的环境怎么配置。

## 3. 不同环境应该怎么接

同一个协议，在图形界面、终端、容器里的"填法"不同。先判断你的工具跑在哪种环境。

### 3.1 图形界面（桌面客户端 / IDE 设置面板）

最常见也最简单：打开设置里的模型/提供商页面，按第 1 节对应面孔填三个值，保存后**完全退出并重新打开**客户端再测。注意：

- 提供方类型选 `OpenAI Compatible` / `Anthropic` / `Gemini` 等协议项，而不是找"NuoAPI"这个名字。
- 部分客户端有"Base URL"和"完整 URL/自定义协议"两种模式，按第 1 节表格对号入座。

### 3.2 命令行：环境变量

先记住各协议面孔对应的常用变量名（具体变量名以工具文档为准）：

| 协议面孔               | 地址变量                                        | 密钥变量                   | 其他                                        |
| ------------------ | ------------------------------------------- | ---------------------- | ----------------------------------------- |
| OpenAI 两协议         | `OPENAI_BASE_URL=https://nuoapi.net/v1`     | `OPENAI_API_KEY`       | Codex 另有 `~/.codex/config.toml` 写法（第 6 节） |
| Anthropic Messages | `ANTHROPIC_BASE_URL=https://nuoapi.net`     | `ANTHROPIC_AUTH_TOKEN` | 根地址，不带 /v1                                |
| Gemini CLI         | `GOOGLE_GEMINI_BASE_URL=https://nuoapi.net` | `GEMINI_API_KEY`       | 另设 `GEMINI_MODEL=模型广场模型名`                 |

**Windows PowerShell：**

```powershell
# 仅当前窗口生效（临时）
$env:OPENAI_BASE_URL = "https://nuoapi.net/v1"
$env:OPENAI_API_KEY = "YOUR_NUOAPI_API_KEY"

# 写入当前用户环境变量（永久，重开终端生效）
[Environment]::SetEnvironmentVariable("OPENAI_BASE_URL", "https://nuoapi.net/v1", "User")
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "YOUR_NUOAPI_API_KEY", "User")
```

**macOS / Linux / WSL（Bash 或 Zsh）：**

```bash
# 仅当前终端生效（临时）
export OPENAI_BASE_URL="https://nuoapi.net/v1"
export OPENAI_API_KEY="YOUR_NUOAPI_API_KEY"

# 永久：写进 shell 配置后 source（zsh 用户换成 ~/.zshrc）
echo 'export OPENAI_BASE_URL="https://nuoapi.net/v1"' >> ~/.bashrc
echo 'export OPENAI_API_KEY="YOUR_NUOAPI_API_KEY"' >> ~/.bashrc
source ~/.bashrc
```

注意：Windows 上通过"系统属性→环境变量"或 `SetEnvironmentVariable` 设置后，**已经打开的终端和 GUI 程序读不到新值**，必须新开终端、或从开始菜单重新启动 GUI 程序。

### 3.3 命令行：配置文件

支持配置文件的 CLI（Codex、Claude Code、Gemini CLI 等）优先用配置文件，可随项目模板分发（只提交占位值）。路径按操作系统区分：

| 工具配置           | Windows                                       | macOS / Linux                                                     |
| -------------- | --------------------------------------------- | ----------------------------------------------------------------- |
| Codex          | `%USERPROFILE%\.codex\config.toml`            | `~/.codex/config.toml`                                            |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Shell 环境配置     | PowerShell `$PROFILE`                         | Bash `~/.bashrc` / Zsh `~/.zshrc`                                 |

Windows 上该目录可能是隐藏目录，可在 PowerShell 中 `mkdir "$env:USERPROFILE\.codex" -Force` 后再编辑；路径含空格或中文时加引号。

### 3.4 Docker 容器与 CI

容器和 CI 里没有"设置面板"，统一走环境变量注入，Key 只能来自密钥管理：

- `docker run`：`-e OPENAI_BASE_URL=https://nuoapi.net/v1 -e OPENAI_API_KEY`（值从宿主机环境带入，不写进镜像）。
- `docker compose`：用 `environment:` 或 `env_file:`，env 文件加入 `.gitignore`。
- CI（GitHub Actions 等）：把 Key 存进仓库/平台的 Secrets，在步骤里映射成环境变量；不要写在 workflow 明文里。
- 容器内访问不到 `127.0.0.1` 上的本地代理时，地址要换成宿主机可达地址（如 `host.docker.internal`），但中转站地址是公网域名，不受此影响。

## 4. 接入 OpenAI 兼容工具

适用于 OpenCode、Cherry Studio、LobeChat、Cursor、Roo Code、Cline、Aider 以及其他提供 OpenAI Compatible 选项的工具（含经中转站使用 Grok 模型的场景）。

在工具设置中填写：

```text
Provider:   NuoAPI
Base URL:   https://nuoapi.net/v1
API Key:    YOUR_NUOAPI_API_KEY
Model:      MODEL_NAME_FROM_MODEL_PLAZA
```

保存后完全退出并重新打开客户端，发送最小测试消息：

```text
请只回复：连接成功
```

OpenCode 的 JSON 模板见 [`../examples/opencode.json.example`](../examples/opencode.json.example)。如果工具要求填写完整路径，通常可从以下入口开始核对：

```text
POST https://nuoapi.net/v1/chat/completions
```

但不要仅凭 HTTP 200 判断高级能力可用。工具调用、流式输出、图片、联网搜索和长上下文都需要分别检查响应字段和实际结果。

## 5. 接入 Claude 类工具

如果客户端明确要求 Anthropic Messages 协议，通常填写站点根地址：

```text
ANTHROPIC_BASE_URL=https://nuoapi.net
ANTHROPIC_AUTH_TOKEN=YOUR_NUOAPI_API_KEY
```

Windows PowerShell 示例：

```powershell
$env:ANTHROPIC_BASE_URL = "https://nuoapi.net"
$env:ANTHROPIC_AUTH_TOKEN = "YOUR_NUOAPI_API_KEY"
```

Claude Code 的配置模板见 [`../examples/claude-code.env.example`](../examples/claude-code.env.example)。配置后重启终端和客户端，再运行版本检查或发送最小请求。

注意：Claude 类工具与 OpenAI 兼容工具的 Base URL 规则可能不同。看到 `404` 时，优先检查是否误加了 `/v1`；看到 `401` 时，检查 Key 是否完整、是否放进了正确的变量。

## 6. 接入 Codex 或其他 CLI

对使用 OpenAI Responses 协议的 CLI，先确认工具支持自定义 Provider，然后按它的配置格式填写：

```toml
model_provider = "nuoapi"
model = "MODEL_NAME_FROM_MODEL_PLAZA"

[model_providers.nuoapi]
name = "nuoapi"
base_url = "https://nuoapi.net/v1"
wire_api = "responses"
requires_openai_auth = true
supports_websockets = false
```

凭据文件只写占位值，实际 Key 放入工具要求的凭据文件或环境变量。Codex 模板见 [`../examples/codex/`](../examples/codex/)。

如果同一工具也支持 Chat Completions（`wire_api = "chat"` 一类取值），只有在 Responses 入口不通、且模型广场表明该模型走 Completions 时再切换，并在自己的记录里注明实际使用的协议，不要混着试。

如果 CLI 持续显示 `Reconnecting`：

1. 确认 Base URL 没有重复拼接 `/v1`。
2. 确认客户端确实使用 HTTP Responses，而不是尝试 WebSocket——日志里出现 `wss://nuoapi.net/v1/responses`、`WebSocket connection ... failed` 或 `stream error` 就是没关掉。
3. 保存配置后完全退出并重新启动 CLI。
4. 用最小请求验证，不要直接运行长时间自动化任务。

## 6.5 用 CC Switch 图形化管理 Provider

CC Switch 是一个开源图形工具，把 Claude Code、Codex、Gemini CLI 的 Provider 配置放在同一个界面里管理，少手写 TOML、JSON 和环境变量。先记住它的边界：**CC Switch 只负责读写本机配置文件、切换当前 Provider，不代理任何网络流量**；目标 CLI 仍要先按 2.5 节装好并能正常运行（`claude --version` / `codex --version` / `gemini --version` 有输出）。

### 6.5.1 安装 CC Switch

下载页（GitHub Releases）：<https://github.com/farion1231/cc-switch/releases>

- **Windows**：优先在 Assets 区下载最新 `.msi`，双击后按 Next / Install 安装，完成后从开始菜单搜索 CC Switch 打开。找不到 `.msi` 时下载 `.zip` 便携版，解压到任意目录后双击 `cc-switch.exe`。
- **macOS**：可用 Homebrew，或下载 Releases 中的安装包。
- **Linux**：按发行版选 `.deb` / `.rpm` / AppImage。

开始菜单里能找到并打开 CC Switch，就是安装完成。

### 6.5.2 从 NuoAPI 一键导入（最省事）

1. 打开 NuoAPI 控制台的 API 密钥页面。
2. 找到要使用的 Key，点击"导入到 CCS"。
3. 浏览器提示"打开外部应用"时选择允许，CC Switch 会自动启动并带入该 Key 的配置。
4. 回到 CC Switch，确认对应工具标签下该 Provider 已被设为"当前使用"。

如果浏览器没有弹窗，或点了没反应，改用下面的手动方式。

### 6.5.3 手动添加 Provider

在 CC Switch 中：点对应工具标签 → 点 + 添加 Provider → 填地址、粘贴 NuoAPI Key → 保存并设为当前使用。地址按工具区分（与第 1 节表格一致）：

| 工具 | Provider 地址 |
| --- | --- |
| Claude Code | `https://nuoapi.net`（根地址，**不加 /v1**） |
| Codex / OpenAI 兼容工具 | `https://nuoapi.net/v1` |
| Gemini CLI | `https://nuoapi.net`（根地址，即 `GOOGLE_GEMINI_BASE_URL`） |

注意：旧版教程此处写的是 `nuoapi.com`，那是旧站域名；新站一律使用 `https://nuoapi.net`（区别见 FAQ 第 13 节）。Gemini 模型还要确认当前分组支持，并在工具配置里写对模型名。

### 6.5.4 保存后重启客户端

Provider 写入后，**完全退出并重新打开**对应的 Claude Code / Codex / VS Code 窗口。界面配置正确但 CLI 不生效，几乎都是客户端还在读旧配置。在 CC Switch 里点测试可用、且配置标记为"当前使用"，即成功；导入后不生效的排查见 FAQ 第 10 节。

## 7. 接入 IDE 插件

Cursor、Roo Code、Cline、Continue 等插件通常在设置中提供以下字段：

```text
Provider: OpenAI Compatible
Base URL: https://nuoapi.net/v1
API Key:  YOUR_NUOAPI_API_KEY
Model:    MODEL_NAME_FROM_MODEL_PLAZA
```

完成后先测试单轮对话，再测试代码补全，最后才测试多文件编辑或自动执行。插件可能会额外发送系统提示词、工具定义和上下文文件，因此一次成功的短消息不能代表全部功能都可用。

## 8. MCP 工具不是模型 API

MCP Server 是本地工具扩展，例如文件系统、浏览器或数据库连接；它与模型 API 的 Provider 配置是两件事：

- 模型 API：负责生成模型响应，配置 Base URL、API Key 和模型名。
- MCP Server：负责提供本地工具，配置启动命令、参数和允许访问的目录。

不要把 MCP Server 的启动命令或本地目录填进 API Base URL。Claude Desktop 的示例见 [`../examples/claude_desktop_config.json.example`](../examples/claude_desktop_config.json.example)。只允许 MCP 访问必要目录，不要把包含密钥、浏览器 Cookie 或个人文件的目录直接暴露给工具。

## 9. 新兴客户端逐个接（ZCode、WorkBuddy、Marvis、Qoder、Trae CN、dsh）

> 下列入口与字段来自各产品公开文档/官方公告，**取证窗口 2026-10-06**，界面会随版本变化，以你本机版本为准。这些工具没有发明新协议，底层仍是第 1 节那四张面孔；每个工具接完都要按第 11 节做最小验收（固定短句测活 + 控制台核对调用记录）。

### 9.1 ZCode（智谱 Z.ai 桌面端）

官方支持添加任意 Anthropic / OpenAI 兼容服务（含本地部署）：

1. 点对话框里的模型名 → 列表底部「管理模型」，进入「Agents 设置 / 模型」面板；在左侧提供商列表底部点「添加提供商」。
2. 名称自取；地址二选一（也可都填）：
   - OpenAI 兼容 Base URL：`https://nuoapi.net/v1`
   - Anthropic 兼容 Base URL：根地址 `https://nuoapi.net`（不带 `/v1`）
3. 填 NuoAPI 的 API Key；确认地址后新版会自动拉取模型列表，也可用「添加模型」手填模型 ID（照抄模型广场）。
4. 打开启用开关，回模型选择器选中该模型后测活。

两个注意点：

- 代理在「设置 → 常规 → HTTP 代理」单独配置，**该字段留空表示直连，不读取 `HTTP_PROXY` 等系统变量**，改完代理要重启应用。
- 另有命令行 zcode 使用 `~/.zcode/v2/provider_config.json`（协议字段 `openai-chat-completions` / `openai-responses` 加 `baseUrl`）的说法来自第三方仓库文档，**C 级、未单点证实**；桌面端图形配置才是官方文档明确记载的路径。

依据：ZCode 官方文档《Connect Models》《API key 配置》（zcode.z.ai，取证窗口 2026-10-06）。

### 9.2 WorkBuddy（腾讯云桌面 Agent）

WorkBuddy 的「自定义 API」是 OpenAI Chat Completions 形态，且**接口地址要填完整路径**，不像多数客户端那样只填前缀：

1. 左下角账户（头像）→ 设置 → 模型 → 自定义模型 → 添加模型；提供商选「自定义 / Custom」。
2. 接口地址：`https://nuoapi.net/v1/chat/completions`
3. API Key：NuoAPI Key（官方说明配置参数含 Key 仅保存在本地 `~/.workbuddy/models.json`，不上传云端）。
4. 模型名称：照抄模型广场的精确模型 ID（该字段就是服务端 `model` 参数，**不支持自定义别名**）。
5. 高级工具（工具调用 / 图片输入 / 推理模式）按模型真实能力勾选，不要无脑全勾；保存后在模型选择器选中，列表里不出现就重启 WorkBuddy。

也可直接写配置文件 `~/.workbuddy/models.json`（Windows 为 `%USERPROFILE%\.workbuddy\models.json`），文件必须存成 **UTF-8 无 BOM**：

```json
{
  "models": [
    {
      "id": "MODEL_NAME_FROM_MODEL_PLAZA",
      "name": "MODEL_NAME_FROM_MODEL_PLAZA",
      "vendor": "Custom",
      "url": "https://nuoapi.net/v1/chat/completions",
      "apiKey": "YOUR_NUOAPI_API_KEY",
      "supportsToolCall": true,
      "supportsImages": false
    }
  ]
}
```

依据：腾讯云《WorkBuddy Enterprise 模型配置》（更新于 2026-09-07）、腾讯云国际站 TokenHub 接入 WorkBuddy 文档（2026-09-21）与腾讯云开发 CloudBase 文档。

### 9.3 Marvis（腾讯操作系统级 AI 管家）

- 入口：设置 → 模型管理 → 自定义模型（该功能 2026-09-01 上线，Mac / Windows / iOS / 安卓 / iPad 均可用）。
- 界面内置腾讯云、DeepSeek、阿里云等快捷项，并保留「自定义模型」入口，可接入采用行业通用接口标准的第三方服务与本地部署模型；自定义模型走**你自己的账户**计费，不占用每日免费额度；配置绑定账号、跨设备同步。
- **字段级填法证据不足**：截至取证窗口官方只发布了功能新闻，没有公开字段文档。先按 OpenAI 兼容套路试：界面要「基础地址 / Base URL」就填 `https://nuoapi.net/v1`，要「完整接口地址」就填 `https://nuoapi.net/v1/chat/completions`，模型 ID 照抄模型广场；报 404 就在两种填法之间切换，并对照第 12 节错误表排查。

依据：科技日报 2026-09-01、新华网 2026-09-24、腾讯科技相关报道（B 级，可证实功能与入口存在；具体字段为推断，C 级）。

### 9.4 Qoder（国际版 IDE / Qoder CLI / Qoder CN）

同名产品有三种形态，能否接第三方网关**不一样**，先分清你用的是哪个：

| 形态 | 自定义端点支持 | 取证 |
| --- | --- | --- |
| Qoder 国际版 IDE（qoder.com） | 支持。Settings → Models → + Add → Custom Base URL，Provider 选 OpenAI Compatible（再选 Chat Completions API 或 Responses API）或 Anthropic Compatible，填 Base URL + API Key + Model ID，Validate and Add | 官方文档 docs.qoder.com |
| Qoder CLI（国际版与 CN 版，v1.1.50 起） | 支持。对话框输入 `/model`，Tab 切到 Custom 页，Add custom model（或按 `n`）→ 选 OpenAI-compatible / Anthropic-compatible → 依次填 Base URL → Model ID → 名称 → Key → 模型能力（上下文长度留空默认 128K，按模型实际值改）→ 保存，切到新模型发条消息确认 | 官方论坛公告 2026-09-12 |
| Qoder CN IDE 个人专业版（lingma.aliyun.com） | **截至帮助文档更新（2026-07-03）只有百炼 / 智谱 / Kimi / MiniMax 四家预置提供商，没有任意 Base URL 入口**——在这个入口里接 NuoAPI 的结论是「不匹配」，请改装/改用 Qoder CLI，或等新版放开后再核实。企业版可由管理员在控制台「策略配置 → 推理服务配置」统一下发 URL、模型名与 Key | 阿里云帮助中心 |

前两种形态的填值：

- OpenAI-compatible：Base URL `https://nuoapi.net/v1`，Key 用 NuoAPI Key，Model ID 照抄模型广场。
- Anthropic-compatible：Base URL 填根地址 `https://nuoapi.net`。

### 9.5 Trae CN（TRAE 国内版桌面端 / TraeCode）

1. 设置 → 模型 → 添加模型 → 选「自定义模型」（自定义模型仅桌面端提供；官方社区明确不支持接入本地模型）。
2. API 格式二选一：**OpenAI Chat Completions** 或 **Anthropic Messages**。
3. 「自定义请求地址」旁有**完整 URL 开关**：
   - 关闭开关（推荐）：只填基础地址，由 TraeCode 自己拼路径——OpenAI 格式填 `https://nuoapi.net/v1`，Anthropic 格式填根地址 `https://nuoapi.net`。
   - 打开开关：填完整路径，例如 `https://nuoapi.net/v1/chat/completions`。
4. 模型 ID 照抄模型广场，填 NuoAPI Key；高级配置（上下文窗口、图片输入等）按模型真实能力设置。保存后在对话框右下角**切换到该模型**——停留在 Auto / 内置模型上会误以为"配置没生效"。
5. 报 404 先怀疑完整 URL 开关两种填法搞反；报 400 先查 API 格式与模型 ID。

依据：Trae 官方文档《内置模型 & 自定义模型》（docs.trae.cn/ide_models，取证窗口 2026-10-06）。

### 9.6 dsh（DeepSeek Harness）

dsh 是 DeepSeek 官方开源的本地 Agent 运行时（npm 包 `@deepseek-ai/dsh`，命令名 `dsh`，含 Web UI 与 headless），模型以自定义 Provider 形式接入。需要 Node.js `^22.19.0` 或 `>=24.0.0`；官方声明仍为开发者预览，配置格式可能随版本变化。

Web UI（推荐）：

1. 在工作目录运行 `npx -y @deepseek-ai/dsh web`（全局安装用 `pnpm add -g @deepseek-ai/dsh`），打开后进入 Settings → Models → Add a custom provider。
2. Provider ID / 名称自取（如 `nuoapi`）；Base URL 填 `https://nuoapi.net/v1`；API protocol 选 `openai-completions`（覆盖面最广；`openai-responses` 只有部分模型接受）；填 NuoAPI Key。
3. 点 Fetch available models 拉取并勾选模型，Create provider 后回会话在模型选择器中选用。

也可直接编辑 `~/.dsh/settings.yaml`（Windows 为 `%USERPROFILE%\.dsh\settings.yaml`）：

```yaml
agent-default-model:
  provider: nuoapi
  model: MODEL_NAME_FROM_MODEL_PLAZA

llm-pi-ai:
  providers:
    nuoapi:
      api: openai-completions
      baseURL: https://nuoapi.net/v1
      apiKeyEnv: NUOAPI_API_KEY
      models:
        - id: MODEL_NAME_FROM_MODEL_PLAZA
```

Key 通过 `NUOAPI_API_KEY` 环境变量注入（用 Web UI 录入则写在同目录 `.credentials.yaml`），不要明文写进 yaml、截图或提交 Git。Anthropic 系协议（`anthropic-messages`）的 Base URL 试填根地址 `https://nuoapi.net`；该形态下 dsh 具体如何拼路径**未单点证实**，拉取模型失败就退回 `openai-completions`。

依据：阿里云百炼《DeepSeek Harness》接入文档及多家集成商公开配置（对应 dsh 0.1.2-rc.1 前后版本，取证窗口 2026-10-06）。

### 9.7 接不了中转站的：MiniMax CLI（mmx-cli）

MiniMax 官方 CLI（npm 包 `mmx-cli`，`mmx auth login --api-key`）区域只有 `cn` / `global` 两档并按 Key 自动判定，文档中没有自定义 Base URL 入口——**不能**把它指向 NuoAPI 这类第三方网关（三态结论：不匹配；依据 MiniMax 官方《MiniMax CLI》文档，取证窗口 2026-10-06）。它的 `mmx agent setup` 作用恰好相反：是把 Claude Code、Codex 等客户端接到 MiniMax 官方端点。要在编程助手里用经 NuoAPI 中转的 MiniMax-M3 等模型，应在支持自定义端点的客户端（Claude Code、Codex 或本节其余工具）里填 NuoAPI 地址与对应模型 ID。

## 10. 查询余额与额度（sub2api 类网关）

NuoAPI 这类 sub2api 形态的网关通常提供只读额度接口：`GET https://nuoapi.net/v1/usage`，鉴权与对话接口相同（Bearer 头，Key 不进 URL）。注意：响应字段层级没有统一标准（`remaining` / `quota.remaining` / `balance`），解析要多级兜底；并先校验 `Content-Type: application/json`，防止 SPA 兜底把 200 HTML 当成功。

完整的探路命令、JS/Python 兼容解析、错误码对照与取证记录模板已独立成篇：[`余额与额度查询-2026-10-06.md`](余额与额度查询-2026-10-06.md)。该端点截至 2026-10-06 为 C 级证据（未单点实测），以实际响应为准。

## 11. 最小验收流程

每个工具至少完成以下检查：

1. 发一条只要求固定短句的请求。
2. 检查客户端没有持续重连、超时或静默降级。
3. 在服务控制台核对刚才的调用记录、模型名和时间。
4. 再测试该工具真正需要的能力，例如流式输出或工具调用。
5. 记录状态码、错误正文、模型名和时间；分享日志前删除 Key、Authorization header 和敏感输入。

“模型列表中出现”只说明列表接口返回了该名称，不等于当前 Key、分组和上游账号池一定能够成功调用。真伪或能力结论只能写成“匹配 / 不匹配 / 证据不足”，不能把没有出现某个关键词写成通过。

## 12. 常见错误

| 现象                              | 优先检查                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| `401 Unauthorized` / `{"code":"API_KEY_REQUIRED"}` | Key 是否完整、是否已撤销、变量名是否正确（Claude 用 `ANTHROPIC_AUTH_TOKEN`）                                      |
| `404 page not found`            | 请求落到了未注册路径：Base URL 是否多了或少了 `/v1`，或客户端拼出的完整路径不对                                            |
| `404 model_not_found` / `model not found` | 模型名是否从当前账户列表复制、Key 分组是否含该模型；Codex 类工具是否选错 `wire_api`（Responses/Chat Completions）                |
| `400 platform is not gemini` 等 platform/protocol 不匹配 | 协议面孔选错（如把 Gemini 原生地址填给了 OpenAI 客户端），回第 1 节对照                                              |
| `400 requires an image model`   | 图片生成模型名前缀不在网关白名单，核对模型广场里的精确图片模型名                                                          |
| `403` 或 `502`                   | 当前分组、上游账号池和服务状态；保留错误正文后再联系服务方                                                              |
| `ETIMEDOUT` / `ECONNRESET` / `socket hang up` / `fetch failed` | 本机网络、代理与防火墙；这类字样与 Key、模型无关                                                            |
| 一直 `Reconnecting`               | 是否误启用 WebSocket（日志出现 `wss://.../v1/responses`），是否已完全重启客户端                                          |
| 改完环境变量仍不生效                      | 是否已新开终端/重启 GUI；Windows 用户级变量不会注入已运行进程                                                      |
| 客户端有回复但控制台无记录                   | 是否实际使用了另一个 Provider、环境变量或官方账户                                                              |
| HTTP 200 但工具不可用                 | 检查响应字段、工具调用结果和实际输出，不要只看状态码                                                                 |
| `POST /v1/embeddings` 返回 404 | 取证窗口 2026-09-21 该路由未挂载即返回 Gin 裸 404；这不是 Key 或模型问题，换 Gemini 路径试探也没有意义。需要向量能力时先重新探一次（零依赖脚本见 [`../examples/embeddings.py`](../examples/embeddings.py)） |
| `POST /v1/audio/speech` 返回 404 | 取证窗口 2026-09-21 为 Gin 裸 404（TTS 路由未挂载）；记"该窗口不支持"，不要写成"模型不支持 TTS"——路由缺失与模型能力是两件事 |
| 余额接口 200 但 `remaining` 为空        | 先看 `Content-Type`：可能是 SPA 兜底返回的 HTML，不是 JSON；实际字段结构见[余额与额度查询专篇](余额与额度查询-2026-10-06.md) |

## 13. 安全收尾

- 测试完成后撤销临时 Key，或限制额度和权限。
- 不要把真实配置文件复制进公开仓库；提交前运行 `git diff --check` 并检查敏感字符串。
- 发生 Key 泄露时立即撤销并重新创建，不要只修改本地文件。
- 不要把第三方网关当作官方服务；购买前单独核对价格、余额扣除、退款、隐私和故障转移规则。

相关模板和示例集中在 [`../examples/README.md`](../examples/README.md)，常见排错见 [`../FAQ.md`](../FAQ.md)。
